# 2026-08-23 工作日志

## 修复：公众号行内样式（加粗/斜体/高亮/代码/删除线）丢失问题

### 问题
编辑器"复制到公众号"功能中，**加粗**、*斜体*、==高亮==、`行内代码`、~~删除线~~ 在公众号编辑器内样式全部丢失。

### 根因
双重嵌套导致：
1. 所有 6 个主题模板的行内组件（inlineStrong/Em/Highlight/Code/Delete）硬编码了 `<span style="..."><span leaf="">{{content}}</span></span>` 嵌套结构
2. `leaf-wrapper.ts` 的 `wrapLeaf` 函数未跳过已有 style 的 span，导致进一步嵌套
3. 公众号编辑器的粘贴净化器会合并/剥离嵌套的行内 `<span>`，导致样式丢失

### 修复（2 处改动）
1. **`src/xumd-gzh-render/leaf-wrapper.ts`**：增加对 `<span style="...">` 直接子文本节点的跳过逻辑
2. **6 个主题模板文件**（moyu-green/graphite-min/red-white/moyu-ticket/olive-note/zen-empty）：移除行内组件中的 `<span leaf="">{{content}}</span>` 嵌套，改为直接输出 `{{content}}`

### 结果
行内元素从 `<span style="X"><span leaf="">文字</span></span>` 变为单层 `<span style="X">文字</span>`

## 第二次修复：改用语义化 HTML 标签

### 问题
单层 `<span style="...">` 仍被公众号编辑器剥离样式。公众号只认语义化标签的格式。

### 修复（3 处改动）
1. **6 个主题模板**：行内组件全部改为语义化标签
   - `inlineStrong`: `<span style="font-weight:...">` → `<strong>`
   - `inlineEm`: `<span style="font-style:italic">` → `<em>`
   - `inlineDelete`: `<span style="text-decoration:line-through">` → `<del>`
   - `inlineCode`: `<span style="font-family:monospace">` → `<code>`
   - `inlineHighlight`: `<span style="background:...">` → `<mark>`
   - `inlineUnderline`: `<span style="border-bottom:...">` → `<u>`
2. **leaf-wrapper.ts**：skipTags 新增 `strong/em/del/s/u/mark/b/i`，不再对这些标签内部文本包裹 leaf span

### 最终输出示例
```html
<strong style="color:#059669;">加粗文字</strong>
<em>斜体文字</em>
<mark style="background:#FDE68A;">高亮文字</mark>
<code style="font-family:monospace;">行内代码</code>
<del>删除线</del>
```

## 第三次修复（最终方案）：清理 `<span leaf="">` 包裹

### 问题
改用语义化标签后，公众号编辑器**所有文字内容全部消失**（比之前更糟）。

### 根本原因
`leaf-wrapper.ts` 的 `wrapLeaf` 函数在渲染管线第 7 步，把**所有文本节点**（包括段落文字、列表项、普通文本）都包上了 `<span leaf="">`。公众号编辑器的粘贴解析器无法正确处理这种嵌套结构，导致内容全部丢失。

### 关键发现（来自 v5 完整 HTML 日志）
复制出的 HTML 中仍大量存在 `<p><span leaf="">文字</span></p>` 结构，尽管 inline 组件已是语义标签。

### 修复（最终生效）
在 `src/xumd-gzh-render/index.ts` 渲染管线第 10 步新增 `unwrapLeafSpans()` 函数：
- 预览版（previewHtml）保留 `<span leaf="">` 不变（用于 CSS 样式定位）
- 复制版（copyOutputHtml）在返回前移除所有 `<span leaf="">` 包裹

## 第五次修复：编辑器深色模式对齐微信官方深色配色

### 问题
编辑器预览的深色模式用的是自定义 Tailwind 石板蓝灰（#0f172a/#1e293b/#e2e8f0/#94a3b8），与微信真实深色模式（中性灰）完全不同，导致"编辑器深色模式 ≠ 微信深色模式"。

### 微信官方深色模式规则（developers.weixin.qq.com 插件规范 + 实测）
- 文章背景：RGB(36,36,36) = `#242424`（柔和深灰，非纯黑）
- 深色文字反相：`#232323`→`#c3c3c3`，`#333333`→`#b3b3b3`
- **彩色（高饱和）文字/背景：保持不变**（微信不转换颜色）
- 渐变背景：先 mix 成纯色再转换

### 修复
1. `src/utils/darkModePreview.ts`：重写 `bgLightToDark`/`textDarkToLight`/`borderLightToDark` 目标色为微信中性灰（#242424/#c3c3c3/#b3b3b3/#d6d6d6/#3a3a3a），代码块背景 #1e1e1e，分割线 #3a3a3a
2. `src/components/PreviewPane.vue`：`.preview-pane.dark` 的 CSS 变量改为微信同款（--preview-*-bg: #242424, --pane-title: #c3c3c3 等）

### 注意
编辑器外壳（sidebar/toolbar/modal）深色配色保持原石板灰不变——那只是编辑环境 UI，无需与微信一致；只有"内容预览"需要匹配微信。

### 复制策略变更
- v4 尝试 `execCommand('copy')` 作为主方案 → 导致公众号文字全消失 → 回退
- 最终方案：`navigator.clipboard.write()` (Clipboard API) 作为主方案，execCommand 降级

### 结果
用户确认：**复制到公众号后，加粗/斜体/高亮/行内代码/删除线 全部正常显示** ✅

### 清理工作
删除调试产物：dist-new, dist-v2~dist-v6, render-harness.mjs, tmp/, vite.config.ts.timestamp-*.mjs
清理调试代码：App.vue 和 useClipboard.ts 中的 console.log 调试语句
最终构建重新生成到 dist/ 目录。

## 第四次修复：签名区微信深色模式文字不可见

### 问题
微信手机预览深色模式下，签名区 "THANKS FOR READING" 文字为深色，与深色背景融为一体看不清。编辑器内深色模式正常显示。

### 根因
moyu-green 签名区使用 `radial-gradient(..., #FFFFFF)` 渐变背景，微信深色模式会**剥离 CSS 渐变**，但保留内联 `color` 样式 → 深色文字 + 深色/透明背景 = 不可见。

### 修复
所有 6 个主题的签名区 `section` 改为纯色实底背景：
- moyu-green: `radial-gradient` → `background:#FFFFFF`
- graphite-min / zen-empty / red-white: 新增 `background:#FFFFFF`
- olive-note: 保持 `#1e1f23`（本身是暗色主题）
- moyu-ticket: 已有 `#fff`（无需改动）
